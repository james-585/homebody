# M1 — Trust and reliability

Status: Draft, awaiting human approval · Author: architect · Date: 2026-10-31
ADRs (all Accepted by James in chat on 2026-10-31): [0001 modules](../decisions/0001-evolve-single-file-with-native-modules.md) · [0002 storage](../decisions/0002-storage-engine-and-schema-versioning.md) · [0003 service worker](../decisions/0003-service-worker-precache-and-update-flow.md) · [0004 exercise identity](../decisions/0004-exercise-identity-and-side-encoding.md)

## Goal
After M1 a user can trust HomeBody with their history: it opens and logs in airplane mode, updates never interrupt a workout, a failed save is visible, data survives schema changes through tested migrations with a way back, the app nudges for backups, and history, PRs and plans survive exercise renames, with the orphaned names in real data counted again. No training-logic changes, no UI redesign, no sync or accounts.

Priority order (human): 1. offline and updates (K1, K4) · 2. data safety (K2, K17) · 3. stable exercise IDs (K3, K16).

## Findings that shape the plan
- No toolchain or tests exist. Node 22 is available. `persistSave` (17 call sites) swallows errors. Import overwrites everything with no snapshot. `persistLoad` deletes legacy keys after copying them.
- The SW precaches only `manifest.json`, calls `skipWaiting()` on install, and is registered as `sw.js?v=7` (cache `homebody-v11`). index.html has two overlapping update-banner implementations and polls every 60 s.
- Fixture, measured: 149 workouts (99 with notes+rpe, 26 rpe only, 24 neither), 1,377 entries, 474 suffixed (237 L/R adjacent pairs; 248 with `bilateral`/`side`, 226 suffix only). **10** orphan names in history (87 entries, 56 workouts), **11** including PR keys (adds KB Lateral Raise). K16 says 12 and cites Farmer's Walk, which is in the current library; see open questions.
- Most stats sites strip the suffix before lookup; the orphans are what is silently skipped.

## Target structure (end of M1)
```
index.html            shell + legacy inline script (shrinking); <script type="module" src="src/boot.js">
sw.js                 tiny SW; VERSION + PRECACHE block generated by scripts/stamp-sw.mjs
fonts/                Oswald, Inter woff2 + OFL.txt
src/boot.js           opens storage, runs migrations, publishes window.HB, calls window.hbStart()
src/storage/          engine-idb.js, engine-local.js, store.js, migrations/NNN-*.js, migrate.js,
                      project-v1.js, import-export.js, validate.js
src/core/exercises.js pure resolve(nameOrId) -> {id, label, side}
src/data/             exercise-ids.js, exercise-aliases.js
scripts/              serve.mjs, stamp-sw.mjs, gen-exercise-ids.mjs (one-off), drift-report.mjs
tests/unit/           node:test: migrations, resolver, data integrity, projection, validation
tests/e2e/            Playwright: characterisation, offline, update, write-failure, import
tests/golden/         characterisation outputs (frozen clock)
tests/fixtures/synthetic/  derived-from-code samples for formats with no real sample (labelled)
```
Interfaces the legacy script may use (all on `window.HB`, documented in docs/architecture.md):
`HB.storage.save(state) -> Promise<void>` · `HB.storage.status() -> {engine, persisted, lastBackupAt, error?}` · `HB.storage.snapshots()` / `restore(id)` · `HB.io.exportFile(state)` / `HB.io.importFile(file) -> {summary, apply(), undo()}` · `HB.exercises.resolve(nameOrId)` · `HB.release.version`.

## Test approach
- **First harness (T1):** characterise before changing. Playwright drives the real index.html with the real-shape fixture and a frozen clock and stores goldens of what users see and what legacy functions return (classic-script globals such as `state` and `mGetLastPerformance` are reachable from `page.evaluate`). These goldens guard every later task; only T11/T12 may change them, and only with a drift report.
- **Unit (node:test):** migrations, resolver, projection, validation and data integrity are pure modules imported directly. Every migration runs against every fixture in `tests/fixtures/legacy/` and `tests/fixtures/synthetic/` with shared invariants.
- **Engine contract tests:** one suite run against both storage engines (IndexedDB via Playwright page context; localStorage likewise).
- **e2e:** offline, SW update (two builds served by `scripts/serve.mjs` from different directories), write-failure injection, import/undo, legacy upgrade from the pre-M1 commit.
- **Browsers:** Chromium and WebKit in CI (WebKit approximates iOS Safari; a manual iPhone check is in T3/T4 acceptance by the human).

## Risks
| Risk | Mitigation |
| --- | --- |
| Async boot regresses start-up or breaks init order | T5 measures cold start; goldens unchanged; boot errors fall back to the localStorage engine |
| A bad SW release is pinned in users' caches | Tiny SW, generated version, update e2e tests, documented kill-switch SW |
| First upgrade runs through old page code | T4 e2e from the pre-M1 commit; keep legacy `'skipWaiting'` message |
| Migration bug corrupts history | Pure migrations, invariant tests on every fixture, snapshot before every migration, v1 mirror for rollback, legacy keys never deleted |
| Only one real fixture; legacy-key formats unseen | Synthetic fixtures labelled; human asked for samples; readers tolerant of unknown fields |
| Orphan mapping guessed wrong | Human confirms each alias; unconfirmed become custom exercises, never dropped |
| Stats visibly change when orphans resolve | Drift report, training-scientist sign-off, optional in-app note (open question) |
| Playwright browsers cannot download in some environments | CI installs them; unit tests run without browsers; documented in CLAUDE.md |
| Safari evicts storage for non-installed web apps | persist() + status display + Add to Home Screen advice; backup nudge |
| Multi-tab IndexedDB upgrade blocked | `onversionchange` handling; never interrupt an active workout |

## Assumptions (until the human or advisers say otherwise)
- A1 Backup nudge: show when 14 days have passed since the last export (or since first use) and at least one workout was logged since; Snooze for 7 days; never during a workout. Product numbers, not training claims.
- A2 Supported browsers: current and previous major iOS Safari, Chrome/Android, desktop Chrome/Firefox/Safari.
- A3 Hosted at a GitHub Pages sub-path; all URLs stay relative.
- A4 The v1 localStorage mirror stays for all of M1.
