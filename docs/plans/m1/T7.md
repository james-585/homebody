## Approach
**Pipeline** (`validate.js`, pure, `now` injected, no I/O, never logs imported content):
1. Size: `file.size` over 20 MB refused before reading; `text.length` re-checked. A single leading BOM is stripped. Then `JSON.parse` in try, no reviver. Top level a plain object with `_vaultfit === true`; `workouts` required (an array); `personalRecords`, `bodyMetrics`, `userPlans`, `profile`, `favourites` treated as empty when missing (Replace preview then says "removes your N ..."); confirmed against the step-0 legacy shapes.
2. Version: `_version` integer, absent counts as 1, above `LATEST_SCHEMA` refused. Older versions validated against their own shape, lifted by `runMigrations`, validated again. Each later migration adds a per-version validator and fixture.
3. **Whitelist copy, every kept leaf checked.** Values are copied by name into fresh objects; no `Object.assign`, no setters from parsed objects. No free-form leaf is kept unchecked: a field is either dropped or checked by type and the string rule. Unknown keys are dropped and counted, including `schemaVersion`, `seq`, `hbSeq` at any level and `_name` (not kept on import). Dictionary parts use `Object.create(null)` while checking; `__proto__`, `constructor`, `prototype` keys refused.
4. **Exact types** (H3; field inventory from every writer plus the fixture in step 0): workout `id` safe integer; plan `id` finite positive number <= 2^53 (the fixture's is a float, 1780457733614.9); `totalSets`, `totalVolume`, `calories`, `duration`, `rpe` (0 to 10 or null), `pr.value`, set/rep/time/weight finite and in range; equipment weights finite in range with capped arrays; `level`, `goal`, `sex`, `activity`, `trackType`, `pr.unit` are enums (they reach class names and HTML raw at ~2162, 2269, 4426, 4481); `_progressionLog` entries: dangerous keys refused, integer timestamps, date window applied.
5. **String rule** (H2, once the sinks are fixed). Name-like fields and notes REFUSE `<` and `>`, C0/C1 controls (keep `\n` and `\t`), U+2028/2029, bidi overrides and isolates (U+202A to 202E, U+2066 to 2069) and lone surrogates; nothing is silently stripped, and anything refused is counted and named by record path. ALLOW apostrophe, double quote, backslash, backtick, `&`, parentheses, `+ - — /`, emoji, every script. Caps sit above what the UI can produce: names 500, notes 20,000 (or matching `maxlength` goes on the inputs first). Known issue added: "input fields have no length or character limits; align with the import rule (T8)".
6. **Dates:** strict ISO-8601 regex (not `Date.parse`, which accepts `2026-01-01 (<img ...>)`), then range check; window 2000-01-01 to `now` + 366 days, warn after `now` + 1 day; applies to workout `date`, body `date`, `_exported`, `_progressionLog`.
7. **Bounds:** workouts 20,000; exercises per workout 100; plans 200; plan days and exercises per day capped; body rows 20,000; PRs 2,000; favourites 1,000; walked depth fixed at 6.
8. Result `{ok:false, reason, where}` (fixed codes; `where` is a record path, never the value; first 20 problems) or `{ok:true, doc, warnings, brand}`. Any invalid record rejects the whole file and changes nothing. The validated doc is branded in a module-private `WeakSet`.
9. **Step 0 oracle:** the real fixture validates with zero dropped fields and a deep-equal result, else stop.

**Merge vs replace** (pure `mergeDocs`, `summarize`; default Merge, Replace explicit).
- Workouts: a current workout is never removed or changed. An incoming workout is a duplicate only against **current** data, by `(date, name, canonical JSON of exercises)`; duplicates inside the file are not deduped, so merging into an empty store equals Replace. The merged output has **unique ids**, including duplicates that were inside the file: a colliding id is re-id'd to the smallest unused safe integer above the current maximum (never past 2^53; a crafted 2^53 id cannot collide the scheme). Replace re-ids in-file duplicates too; both counted in the preview.
- PRs: new keys added, existing keys keep your value. Body metrics: union by exact `date`, yours win. Plans: add by unused id, same id keeps yours. Favourites: union.
- **Profile:** under Merge the file's profile is taken only when the current profile is absent or empty, and the preview shows it; Replace shows the profile change.
- A `_partial` file cannot be used with Replace.
- `summarize` returns plain numbers and clipped strings for both modes: counts, date range, `_exported`, new / present / re-id'd, removed-if-replace, dropped and refused counts, future dates, partial, profile change, mirror warning. The UI renders only this.

**Atomic apply and snapshot.** `store.importDoc(input)` runs `validate` itself (or accepts only branded objects; an unbranded object is refused), then: `usable()`; refuse unless loaded, writable (`canWrite()`, `hbLoadedOk` true), on the IndexedDB engine (the localStorage fallback engine is refused entirely, Q3), and with no active workout. **Lock first:** set the `restore`-style `importing` read-only state before `settled()` and keep it until `state.*` is replaced; re-check the active workout after `settled()`. Then one `engine.writeDoc(next, {seq, expectSeq: cur.seq, snapshot:{reason:'pre-import', payload: cur.doc}})`: snapshot, stores and meta in one transaction (a failure leaves the previous state; fixed strings by kind). `seq` comes only from the store. On success the mirror is stamped, the lock released, and the caller replaces `state.*` in the same `.then`, before any tap. The mirror ceiling (M6): if `projectToV1` text would exceed 512K chars, importDoc marks the mirror stale (`status().mirror:'stale'`, as for any failed mirror write) and the preview warns before apply; the IndexedDB commit is still the save. Only the newest 5 `pre-import` snapshots are kept (existing per-reason retention).
**Undo** = `restore(snapshotId)` with its own `pre-restore` snapshot, then reload. It is offered only while store `seq` still equals the import's commit (nothing saved since, in any tab); otherwise hidden or the designer's warning says later changes will be removed. Refused while a workout is active. Known gaps recorded: `restore` has the same check-then-act gap (add to K40 note); another tab saving stale state can undo the import (`pre-overwrite` keeps it; add to K31).

**K39 and recovery (M5).** `MAX_SEQ = 2^31 - 1`, shared by reader and stamper. `hbSeqOf` captures any `"hbSeq":` token in the tail (`(\d+)` and non-numeric forms) and returns `absent | n | corrupt`; negative, string, exponent, oversized, 11 to 15 digits are **corrupt, not absent**. `decideBoot` ignores a corrupt mirror (IndexedDB wins, mirror left as found, restamped on next save, no `pre-reconcile`); `canFastBoot` refuses it. A seq above `MAX_SEQ` in `meta` reads as corrupt. The stamper refuses to write above it. **Recovery for installs where it already happened** (`meta.seq` near 1e15 would otherwise lock read-only forever): a boot-time renumber transaction that takes a `pre-reconcile` snapshot, resets `meta.seq` to `max(valid mirror seq, 1)` and re-stamps the mirror; if that fails the store is read-only with the existing bar and Export, and a known issue says so. Both need a fixture (a mirror with a 15-digit `hbSeq`, a `meta` with `seq` 1e15).

**Export** (pure `buildExport(state, {now, partial})`, **compact JSON**). Same six sets plus `_vaultfit`, `_version = LATEST_SCHEMA` (2), `_exported`, `_containsHealthData: true`; `_name` dropped from the header (L3; the profile name is still inside `profile`). Plain Export in unreadable, newer or unavailable states adds `_partial: true` and `_partialReason` (K30). Filenames `HomeBody_<YYYY-MM-DD>.vaultfit`, partial `HomeBody_partial_<YYYY-MM-DD>.vaultfit`; no profile name. `buildExport` measures its output and refuses (designer copy) if it would exceed the import cap, so the app never produces a backup it cannot restore. The raw "as found" `.txt` export stays. Known-issue note added: a pre-M1 build ignores `_partial` and may Replace with a partial file.

**Lazy modules (M4).** The modules load with `import()` on first Import/Export tap, precached by the SW. (a) On load failure refuse with fixed copy and **never fall back to the legacy `mConfirmImport`**. (b) Version-skew guard: modules export `IO_API_VERSION` and `LATEST_SCHEMA`; `HB.io` checks both and refuses with "reload" on mismatch. (c) The URL is built from `hb-storage.js`'s own script URL. (d) `file://` is unsupported, documented in `docs/offline.md`. (e) Modules never log imported content. Verified in Chromium and WebKit, online and offline. **The `hb-storage.js` split is deferred** (Q7); only if asked, measure interleaved median of 5 cold starts, 1 file vs 3 tags, accept within +3%.

## Tests
Lighter standard: one `npm run verify`, small repeat counts.
- `import-validate`: fixture zero-diff; 10+ malformed variants with reason codes and "state unchanged"; threat rows: HTML-looking and entity strings (`&#39;`), `<` `>`, controls, bidi, lone surrogates, `__proto__`/`constructor`, `1e999`, `-0`, strings for numbers, unquoted-onclick fields with strings, enums, `Date.parse`-only dates, BOM, `_version` 0/1.5/"2"/99, counter keys at any level, 20 MB+1 and whitespace, missing `workouts`, partial for Replace; `where` never contains the value.
- `import-fuzz`: seeded PRNG, 2,000 mutations; never throws; input unmutated; `ok` output in range, plain prototypes, `Object.prototype` untouched, fixed point on re-validation.
- `import-merge`: current workouts never dropped; `merge(a,a) = a`; merge into empty equals Replace; unique ids incl. in-file duplicates and a 2^53 id; profile rule; summary equals result.
- `store-import` (fake engines): one-transaction snapshot; interrupted write leaves previous state; refusals (workout, read-only, corrupt, future, fallback engine, not loaded, unbranded doc); workout started during `settled()` is caught; lock held until state replaced; `expectSeq` race; Undo offered only at the commit seq; mirror ceiling; K39 table incl. 11 to 15 digits, negative, string, exponent, and the renumber recovery.
- `import.spec` (Chromium; core `@smoke`): import over different data then Undo, exact state; v1 export and re-export round trip; entity/quote names render as text and execute nothing in the preview and in the favourites and exercise-info sinks; lazy-load failure refuses and never reaches the old path; skew refusal; offline; filename and markers; tap count unchanged; goldens, `offline`, `update`, `idb` specs unchanged. Report validator time (fixture; 20 MB file) and the 20 MB parse in WebKit; stop if fixture over 100 ms or 20 MB over 2 s.
- **Mutation checks, data loss and validation bypass only:** drop the snapshot; write stores outside the snapshot transaction; pass an unvalidated doc to `importDoc`; remove the `__proto__` filter; remove caps; merge overwriting current workouts; let `hbSeq` through; drop the lock before `state.*` is replaced.

## Stop conditions
Stop, report, and wait for the human if any of these happen:
- A file outside **Files**, a new dependency, or an ADR change is needed.
- The real fixture loses a field or changes through the validator.
- An existing test (restore, store, migration, golden) has to be edited to pass.
- Any path could delete, truncate or overwrite data without the same-transaction snapshot, write a seq from a file, or reach `importDoc` unvalidated.
- A sink cannot be made safe within the import path.
- A UI edit is needed before the designer spec is approved, or copy would have to be invented.
- Logging a set takes more than two taps, first paint regresses, offline breaks, or timing limits are exceeded.
- `npm run verify` is red after two honest attempts, or the AC are ambiguous.
