## Approach
**Pipeline** (all in `validate.js`, pure, `now` injected, no I/O):
1. Size: `file.size` over 20 MB (m1.md) is refused before `readAsText`; `text.length` is checked again after reading. Empty or non-string: refused.
2. `JSON.parse` inside try. Top level must be a plain object with `_vaultfit === true`. Never `eval`, never a reviver.
3. Version: `_version` integer; absent counts as 1 (pre-M1 code only ever required `_vaultfit`); above `LATEST_SCHEMA` is refused ("made by a newer HomeBody", fixed string). Older versions are validated against their own shape, then lifted by `runMigrations(MIGRATIONS, ...)`; the migrated result is validated again against the current shape. Rule for later migrations: each adds a per-version validator and a fixture.
4. Schema, whitelist per field: copy values by name into fresh objects (dictionary parts such as `personalRecords` use `Object.create(null)` while checking, keys `__proto__`, `constructor`, `prototype` refused, output built with plain `{}` and `defineProperty`). Types strict (`typeof`, `Number.isFinite`, so `1e999` fails; integers where integers); ranges (weight, reps, sets, time, rpe, RPE 0 to 10 or null, body metrics); strings length-capped (names 120, notes 2,000) and stripped of control characters, U+2028/2029 and bidi overrides; enums for `trackType`, `unit`. Unknown keys are dropped and counted (the preview says how many), **including `schemaVersion`, `seq` and `hbSeq` anywhere in the file**, so a file can never set a counter (K39). Array caps: workouts 20,000; exercises per workout 100; plans 200; plan days and exercises per day small caps; body rows 20,000; PRs 2,000; favourites 1,000. Depth is bounded by the schema (the validator only walks known paths; free-form plan fields are walked to a fixed depth of 6, deeper is refused). Dates: parseable, between 2000-01-01 and `now` + 366 days; later than `now` + 1 day is counted as a warning, outside the window is refused. Duplicate ids: counted and kept as found (stored data may legitimately have them, ADR 0002 amendment); merge resolves them.
5. **Step 0, before any code:** build the field inventory from every writer in `index.html` (`wmFinish`, manual log, body log, plan builder, onboarding) and the fixture. The real fixture must validate with **zero dropped fields and deep-equal output** (principle 1: validation must not silently strip real history). If it does not, stop.
6. Result: `{ok:false, reason, where}` (fixed reason codes, first 20 problems) or `{ok:true, doc, warnings}`. Any invalid record rejects the **whole file** and changes nothing (Q2).

**Merge vs replace (pure `mergeDocs`, `summarize`).** Default is **Merge**, because it cannot remove anything. Replace (today's behaviour) is a second, explicit choice, always preceded by the snapshot.
- Workouts: a workout is a duplicate when `(date, name, canonical JSON of exercises)` matches; ids are not trusted. Duplicates are skipped (yours kept); others are appended; an incoming id that collides with an existing one gets `max id + 1` (deterministic). Ordering rule checked against how the app reads history in step 0.
- PRs: keys you do not have are added; keys you have keep your value (comparing records needs unit-aware direction, a training claim we do not make). Body metrics: union by exact `date`, yours win ties. Plans: add by new `id`, same id keeps yours (as `mImportPlanOnly` does). Favourites: union. Profile: yours kept, unless you have no profile name yet (fresh install), then the file's.
- Replace: all six sets taken from the file. The preview must show "N workouts you have now are not in the file" first. A file flagged `_partial` cannot be used with Replace.
- `summarize(current, incoming)` returns plain numbers and clipped strings for both modes: counts per set, workout date range, `_exported`, new / already present / re-id'd, removed-if-replace, dropped-field count, future-date count, duplicate-id count, partial flag. The UI renders only this object.

**Atomic apply and snapshot.** New `store.importDoc(doc)` modelled on `restore`, sharing one private helper only if all `restore` tests pass unedited: `usable()`; refuse `workout-active` (same rule as restore); refuse unless the store is loaded and writable (the `canWrite()` gate, and `hbLoadedOk` true, so a late storage script or a read-only state cannot be written through); refuse on the localStorage engine (no snapshots, so no safe replace; Q3). Then `settled()`, `readDoc()`, and **one** `engine.writeDoc(next, {seq, expectSeq: cur.seq, snapshot:{reason:'pre-import', payload: cur.doc, keep:false}})`: snapshot, stores and meta in one transaction; another tab's commit in between keeps its state as `pre-overwrite` (existing rule). `seq` comes only from the store. After commit: `stampMirror`, `noteCommitted`, store stays writable, and the caller replaces `state.*` in the same `.then` (before any tap can run) and renders. `importDoc` returns `{snapshotId, summary}`. A mid-transaction failure leaves the previous state intact (fixed error strings by kind; no new copy).
**Undo** = `restore(snapshotId)` (existing): it refuses during a workout, takes its own `pre-restore` snapshot (so the import can be redone), then locks the store read-only until reload, so T7b reloads after a successful Undo. If a workout was started after the import, Undo is refused with the existing kind and stays possible later (the snapshot remains; its list is T8). In read-only or restored states nothing is written.

**K39.** `MAX_SEQ = 2^31 - 1`. `hbSeqOf` matches `\d{1,10}` and returns a distinct "corrupt" result above `MAX_SEQ`; `decideBoot` ignores a mirror with a corrupt or `> meta.seq + 1e6` `hbSeq` (IndexedDB wins, mirror left as found, restamped on next save, no `pre-reconcile`). The stamper refuses to write a seq above `MAX_SEQ` (store locks as `corrupt`); `meta.seq` above it reads as corrupt. The regex and stamper share the one constant. Tests: 15-digit and 11-digit `hbSeq` mirrors boot once, take zero snapshots, and the second boot is identical; a file with `hbSeq`/`seq` keys imports with them dropped.

**Export (pure `buildExport(state, {now, partial})`).** Same six sets and header as today plus: `_version = LATEST_SCHEMA` (2; a pre-M1 build ignores `_version`), `_containsHealthData: true` (machine marker, no prose), and `_partial: true` with `_partialReason` (`unreadable`, `newer`, `unavailable`) when the plain `Export` runs in those states (K30). Filename: `HomeBody_<YYYY-MM-DD>.vaultfit`, partial `HomeBody_partial_<YYYY-MM-DD>.vaultfit`; **the profile name leaves the filename** (Downloads folders, cloud sync and share sheets expose filenames; the name is inside the file anyway) (Q6). `_name` stays in the header for old-build previews. The raw `Export saved file` stays unchanged (`homebody-saved-data-as-found.txt`): it is the only way back when the data cannot be parsed. Visible labels for health data and partial are designer copy.

**Loading and the hb-storage.js split.** `validate.js` and `import-export.js` are ES modules loaded with `import()` on first tap of Import or Export, precached by the SW (stamped), pure and importable by node tests directly; they get `runMigrations`, `MIGRATIONS`, `LATEST_SCHEMA` from `HBStorage` by parameter. First paint is unaffected (nothing new is parsed at start). Verify in Chromium and WebKit that a relative `import()` from the classic script resolves, and that it works offline. **Recommendation: defer the three-way split of `src/hb-storage.js`** (pure section, `createIdbEngine`, `createStore`). The file is 64.6 KB, one classic script on purpose; T7 adds only `importDoc` and K39 (about 100 lines), the biggest code goes to the lazy modules, and a split into three classic tags buys nothing until it can become modules. If James wants it, measure first: interleaved median of 5 cold starts (`hb:rendered`) for 1 file vs 3 tags, plus bytes and request count; accept only within +3% of the 1-file build. Not done in T7 without that approval.

## Security (security-reviewer from the plan stage)
Threat list for the validator and its tests: oversized file (20 MB+1, and 20 MB of whitespace); not JSON / BOM / truncated; deep nesting; huge arrays and huge strings; `__proto__`, `constructor`, `prototype` keys (top level, in PRs, in records); numbers as strings, `1e999`, negative, fractional, `-0`; duplicate ids and duplicate workouts; future and ancient dates; control and bidi characters; strings that look like HTML or `'); alert(1)//` in workout, exercise, plan, day and profile names and notes; `_version` 0, -1, 1.5, "2", 99; counter keys (`hbSeq`, `seq`, `schemaVersion`) at any level; a partial file offered for Replace; a file larger after migration than before.
K15 in this path: preview and error text use text nodes only (never `innerHTML` with imported data; today `mShowImportConfirm` and `mImportPlanOnly` interpolate). After import the data reaches the legacy renderers, so T7 lists every sink that interpolates an imported field into HTML or an `onclick` string; security-reviewer decides the name-field rule at plan review (default proposed: name-like fields refuse `< > \` \ "` and control characters, allow the apostrophe because library names use it, and the audit must show every `onclick` use is escaped; notes are free text but only reach `escHtml`/text nodes). If any sink cannot be shown safe, stop and report.

## Tests
Lighter standard: one `npm run verify`, small repeat counts, no fresh-clone run.
- `import-validate.test.mjs`: fixture validates with zero dropped fields and deep-equal output; the 10+ malformed variants (AC1), each with its reason code and "state unchanged"; the threat list above row by row; size limits.
- `import-fuzz.test.mjs`: seeded PRNG (no new dependency), 2,000 mutations of the fixture (type swaps, deletions, giant strings, `__proto__`, `1e999`, array growth, key duplication). Properties: never throws; input not mutated; `ok` output has finite numbers in range, strings under caps, no own `__proto__`, plain prototypes, arrays under caps; `validate(validate(x).doc)` is a fixed point; `Object.prototype` untouched afterwards.
- `import-merge.test.mjs`: merge keeps every current workout (counts never drop), `merge(a, a) = a`, collision re-id, partial cannot Replace, summary counts equal the applied result.
- `store-import.test.mjs` (fake engines): snapshot and data in one transaction; interrupted write leaves previous state and no snapshot; refuses with workout active, read-only, corrupt, future, localStorage engine, not loaded; `expectSeq` race keeps `pre-overwrite`; mirror and `hbSeq` stamped from store; K39 table; `KEYS` coverage unchanged.
- `import.spec.mjs` (Chromium; core flow `@smoke`): import the fixture over different data, Undo, state equals the pre-import export byte for byte (AC2); v1 export imports and a current export re-imports to identical state (AC3); crafted file with HTML-looking names renders as text and executes nothing; offline import; export filename and partial flag; set-logging tap count unchanged (T7b); goldens, `offline.spec`, `update.spec`, `idb.spec` unchanged. Measure validator time (fixture; a 20 MB file) and report; stop if the fixture takes over 100 ms or a 20 MB file over 2 s.
- **Mutation checks, data loss and validation bypass only:** (a) drop the snapshot from `importDoc` -> Undo test fails; (b) write stores outside the snapshot transaction -> interrupted-write test fails; (c) remove the `__proto__` filter -> fuzz fails; (d) remove the size or array caps -> variants fail; (e) make merge overwrite current workouts -> merge test fails; (f) let `hbSeq` through -> K39 test fails.

## Stop conditions
Stop, report, and wait for the human if any of these happen:
- The change needs a file outside **Files**, a new dependency, or an ADR change.
- The real fixture loses any field or changes through the validator.
- An existing test (including restore, store, migration, golden tests) has to be changed to pass.
- Any import, merge, undo or K39 path could delete, truncate or overwrite data without the same-transaction snapshot, or write a seq taken from a file.
- An imported field reaches an unescaped HTML or `onclick` sink that cannot be fixed within the import path.
- Any UI edit is needed before James has approved the designer spec; any copy would have to be invented.
- Logging a set takes more than two taps, first paint regresses, or offline use breaks.
- Validator timing exceeds the limits above.
- `npm run verify` is red after two honest attempts, or the AC turn out ambiguous.
