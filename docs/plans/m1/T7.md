## Approach
**Pipeline** (`validate.js`, pure, `now` injected, no I/O, never logs imported content):
1. Size: `file.size` over 20 MB refused before reading; `text.length` re-checked. A single leading BOM is stripped. Then `JSON.parse` in try, no reviver. Top level a plain object with `_vaultfit === true`; `workouts` required (an array); `personalRecords`, `bodyMetrics`, `userPlans`, `profile`, `favourites` treated as empty when missing (Replace preview then says "removes your N ..."); confirmed against the step-0 legacy shapes.
2. Version: `_version` integer, absent counts as 1, above `LATEST_SCHEMA` refused. Older versions validated against their own shape, lifted by `runMigrations`, validated again. Each later migration adds a per-version validator and fixture.
3. **Whitelist copy, every kept leaf checked.** Values are copied by name into fresh objects; no `Object.assign`, no setters from parsed objects. No free-form leaf is kept unchecked: a field is either dropped or checked by type and the string rule. Unknown keys are dropped and counted, including `schemaVersion`, `seq`, `hbSeq` at any level and `_name` (not kept on import). Dictionary parts use `Object.create(null)` while checking; `__proto__`, `constructor`, `prototype` keys refused.
4. **Exact types** (H3; field inventory from every writer plus the fixture in step 0): workout `id` safe integer; plan `id` finite positive number <= 2^53 (the fixture's is a float, 1780457733614.9); `totalSets`, `totalVolume`, `calories`, `duration`, `rpe` (0 to 10 or null), `pr.value`, set/rep/time/weight finite and in range; workout `planId` a finite number or absent; any day-index field a non-negative integer; equipment weights finite in range with capped arrays; `level`, `goal`, `sex`, `activity`, `trackType`, `pr.unit` are enums (they reach class names and HTML raw at ~2162, 2269, 4426, 4481); `_progressionLog` entries: dangerous keys refused, integer timestamps, date window applied.
5. **String rule** (H2, once the sinks are fixed). **Name-like fields** REFUSE `<` and `>`; **notes** allow them (the shipped template note at `index.html:1755` contains `>`, and plan-day notes reach only the escHtml text sink at ~4501). Both refuse C0/C1 controls (keep `\n` and `\t`), U+2028/2029, bidi overrides and isolates (U+202A to 202E, U+2066 to 2069) and lone surrogates; nothing is silently stripped, and anything refused is counted and named by record path. ALLOW apostrophe, double quote, backslash, backtick, `&`, parentheses, `+ - — /`, emoji, every script. Caps: names 500, notes 20,000, on import only (Q3); input `maxlength` is T8. **Name-like fields, exactly:** workout `name`; exercise `name`; plan `name`; plan day names and plan exercise names; profile `name`; `personalRecords` **keys** (rendered at ~2266); `_progressionLog` **keys**; favourites entries; any other string that reaches a heading, label, class, attribute or handler (the step-0 inventory finalises the list). Dictionary keys get the full string rule and the 500 cap, not only the `__proto__` check. **Notes:** workout `notes`, plan `desc`/day notes. Known issue added: "input fields have no length or character limits; align with the import rule (T8)".
6. **Dates:** strict ISO-8601 regex (not `Date.parse`, which accepts `2026-01-01 (<img ...>)`), then range check; window 2000-01-01 to `now` + 366 days, warn after `now` + 1 day; applies to workout `date`, body `date`, `_exported`, `_progressionLog`.
7. **Bounds:** workouts 20,000; exercises per workout 100; plans 200; plan days and exercises per day capped; body rows 20,000; PRs 2,000; favourites 1,000; walked depth fixed at 6.
8. Result `{ok:false, reason, where}` (fixed codes; `where` is a record path, never the value; first 20 problems) or `{ok:true, doc, warnings, brand}`. Any invalid record rejects the whole file and changes nothing. The doc is plain data; if a brand is kept it is a module-private `WeakSet` over a **deep-frozen** doc, and it is only an optimisation for the preview, never a way to skip validation.
9. **Step 0 oracle:** the real fixture validates with zero dropped fields and a deep-equal result, else stop.

**Merge vs replace** (pure `mergeDocs`, `summarize`; default Merge, Replace explicit).
- Workouts: a current workout is never removed or changed. An incoming workout is a duplicate only against **current** data, by `(date, name, canonical JSON of exercises)`; duplicates inside the file are not deduped, so merging into an empty store equals Replace. The merged output has **unique ids**, including duplicates that were inside the file: a colliding id is re-id'd to the smallest unused safe integer above the current maximum; **when the maximum is 2^53-1, the smallest unused positive safe integer, or the import is refused with a reason code** (merge tests cover a crafted 2^53-1 id). Replace re-ids in-file duplicates too; both counted in the preview.
- **`mergeDocs` runs inside `importDoc`, after the lock, against `engine.readDoc()`; never in the caller against `state.*`** (state may be stale).
- PRs: new keys added, existing keys keep your value. Body metrics: union by exact `date`, yours win. Plans: add by unused id, same id keeps yours. Favourites: union.
- **Profile:** under Merge the file's profile is taken only when the current profile is absent or empty, and the preview shows it; Replace shows the profile change.
- A `_partial` file cannot be used with Replace.
- `summarize` returns plain numbers and clipped strings for both modes: counts, date range, `_exported`, new / present / re-id'd, removed-if-replace, dropped and refused counts, future dates, partial, profile change, mirror warning. The UI renders only this.

**Atomic apply and snapshot.** `store.importDoc(input)` **always runs `validate` itself** on the raw input (no "already validated" option), then: `usable()`; refuse unless loaded, writable (`canWrite()`, `hbLoadedOk` true), on the IndexedDB engine (the localStorage fallback engine is refused entirely, Q3), and with no active workout. **Lock first:** a new `importing` read-only kind (like `restoring`), set before `settled()`, **added to `mirrorLive` like `restoring`** so the success `stampMirror` is not skipped, and held until `state.*` is replaced; re-check the active workout after `settled()`. Then `engine.readDoc()`, `mergeDocs`, and one `engine.writeDoc(next, {seq, expectSeq: cur.seq, skipOnMismatch: true, snapshot:{reason:'pre-import', payload: cur.doc}})`: snapshot, stores and meta in one transaction. **On a skip (another tab committed) the lock is released and the import is refused** with designer copy ("changed in another tab, preview again"). The lock is released on every failure path, as `restore`'s catch does; on `future`/`corrupt` the store locks with that kind. A failed import leaves the store writable (tested). `seq` comes only from the store. On success the mirror is stamped, the lock released, and the caller replaces `state.*` in the same `.then`, before any tap.
**Mirror ceiling (one gate).** The existing `mirrorText(text, payload, n)` (~858) is extended into the one gate, called by every mirror write: `stampMirror`, `renumberMirror` (~1330), `restampMirror` (~1346), the boot `rewriteMirror` path and the save path (~1449), including provisional plain writes. It refuses to write a mirror over 512K chars (James, Q2): the mirror is marked stale (`status().mirror:'stale'`), the IndexedDB commit is still the save, and the import preview warns before apply. When the gate refuses, the existing mirror is left as it is (marked, seq <= IndexedDB) and `status().mirror` becomes `'stale'`; a provisional save over the ceiling writes no plain text. The gate is **never** applied to the localStorage fallback engine's primary `writeDoc`/`write` (~182, ~1317) or to the legacy-key migration (~879), where it would drop the only copy. Consequences recorded in K42 and `docs/security.md`: existing heavy users above about 1,500 workouts stop updating the mirror; a pre-M1 rollback shows older data; if saved there, the next M1 boot lets import-mirror win over IndexedDB, and the newer data survives only in a `pre-reconcile` snapshot with no UI until T8. Only the newest 5 `pre-import` snapshots are kept.
**Undo** reads `meta.seq` from IndexedDB at tap time (not an in-memory value) and compares it with the import's commit seq; if equal it calls `restore(snapshotId)` (own `pre-restore` snapshot, then reload); if not, the designer's warning says later changes will be removed (`restore`'s `expectSeq` keeps the overwritten state in a snapshot). Refused while a workout is active. Known gaps recorded: `restore` has the same check-then-act gap (K40 note); another tab saving stale state can undo the import (`pre-overwrite` keeps it; K31).

**K39 and recovery (M5).** `MAX_SEQ = 2^31 - 1`, shared by reader and stamper. `hbSeqOf` captures any `"hbSeq":` token in the tail (`(\d+)` and non-numeric forms) and returns `absent | n | corrupt`; negative, string, exponent, oversized, 11 to 15 digits are **corrupt, not absent**. `decideBoot` ignores a corrupt mirror (IndexedDB wins, mirror left as found, restamped on next save, no `pre-reconcile`); `canFastBoot` refuses it. `MAX_SEQ` is enforced in **three places**: the mirror stamper; `writeDoc` (its preflight treats a `meta.seq` that is not an integer or is above `MAX_SEQ` as corrupt, and the transaction aborts if the resulting seq would exceed it); and the sidecar (an `idbSeq` above `MAX_SEQ` is ignored). When an ignored corrupt mirror is about to be overwritten and its text differs from the projected IndexedDB doc, the mirror text is first kept as a `pre-reconcile` snapshot. **Recovery for installs where it already happened** (James, Q1): read-only with the existing bar and Export, plus a known issue; the way out is restore into a fresh store in T8. No automatic renumber: it would break "`meta.seq` never goes backwards", which `expectSeq` relies on (it would need an epoch). Fixtures: a mirror with a 15-digit `hbSeq`, a `meta` with `seq` 1e15.

**Export** (pure `buildExport(state, {now, partial})`, **compact JSON**). Same six sets plus `_vaultfit`, `_version = LATEST_SCHEMA` (2), `_exported`, `_containsHealthData: true`; `_name` dropped from the header (L3; the profile name is still inside `profile`). Plain Export in unreadable, newer or unavailable states adds `_partial: true` and `_partialReason` (K30). Filenames `HomeBody_<YYYY-MM-DD>.vaultfit`, partial `HomeBody_partial_<YYYY-MM-DD>.vaultfit`; no profile name. `buildExport` measures its output and refuses (designer copy) if it would exceed the import cap, so the app never produces a backup it cannot restore; the refusal never leaves the user without an export: the raw `.txt` export stays in the same place and the refusal copy names it. After building, `buildExport` runs the same validator on its own output; if any record would be refused it warns at export time with record paths and still exports. The raw "as found" `.txt` export stays. Known-issue note added: a pre-M1 build ignores `_partial` and may Replace with a partial file.

**Lazy modules (M4).** The modules load with `import()` on first Import/Export tap, precached by the SW. (a) On load failure refuse with fixed copy and **never fall back to the legacy `mConfirmImport`**. (b) Version-skew guard: modules export `IO_API_VERSION` and `LATEST_SCHEMA`; `HB.io` checks both and refuses with "reload" on mismatch. (c) The URL is built from `hb-storage.js`'s own script URL, captured from `document.currentScript.src` when the script first runs (it is null in later async code). (d) `file://` is unsupported, documented in `docs/offline.md`. (e) Modules never log imported content. Verified in Chromium and WebKit, online and offline. **The `hb-storage.js` split is deferred** (Q7); only if asked, measure interleaved median of 5 cold starts, 1 file vs 3 tags, accept within +3%.
