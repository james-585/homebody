## Acceptance criteria
- [ ] Changing any shell file and not re-stamping fails `npm run verify` and CI.
- [ ] Re-stamping with unchanged files is a no-op (stable hash, stable ordering).
- [ ] `sw.js` comment/version drift (v7/v8/v11) gone; cache name is `homebody-<hash>`.
- [ ] CLAUDE.md guardrail text updated: "run `npm run stamp`" replaces the manual bump.

## Approach
Builds on ADR 0003 and the T1 toolchain (`package.json`, `node --test`, Playwright, `scripts/serve.mjs`). The script hashes (SHA-256, first 12 hex chars) every shell file: `index.html`, `manifest.json`, `icon-*.png`, plus `src/**/*.js` and `fonts/*.woff2` when they exist, and `sw.js` itself with the generated block removed. Hashing `sw.js` closes the gap where a logic-only edit to it would otherwise keep the old cache name. Files are sorted by POSIX path in byte order (not locale), and each contributes `path`, a NUL, its byte length, a NUL and its raw bytes. The block sits between `// >>> stamp-sw:begin` and `// <<< stamp-sw:end` and holds `VERSION` and `PRECACHE`; `CACHE` becomes `'homebody-' + VERSION` outside it. `PRECACHE` is a fixed list in the script, `['manifest.json']` in this task, so runtime behaviour is identical (T3 widens it). The stamper writes only if the rendered block differs, and `--check` writes nothing and exits 1 with a message naming the fix. Pure functions are exported for tests; the CLI is a thin wrapper. The workflow uses `ubuntu-24.04`, `permissions: contents: read`, `concurrency` cancel-in-progress, `timeout-minutes`, `actions/checkout` (`persist-credentials: false`) and `actions/setup-node` (built-in npm cache; Node 22), all pinned by full commit SHA resolved from GitHub at implementation (never typed from memory), then `npm ci`, `npx --no-install playwright install --with-deps chromium webkit` and `npm run verify`. No secrets, no `pull_request_target`, no other actions.

## Tests

## Stop conditions
Stop, report, and wait for the human if any of these happen:
- The change needs a file outside **Files** above, or a new dependency.
- An existing test has to be changed or deleted to make the new code pass.
- A storage change has no migration, or a migration fails on any fixture in tests/fixtures/legacy/.
- A strength standard, MET value, volume target or other training number would have to be written without a source or documented rationale.
- A new external request, third-party script, notification, health-platform link or data source is needed, or a secret seems necessary.
- Exercise data would have to be retyped by hand rather than extracted or sourced.
- The change makes logging a set take more than two taps, or breaks offline use.
- The 'verify' command is still red after two honest attempts.
- The acceptance criteria turn out to be ambiguous or contradict the spec.
- Satisfying an AC needs a change to `sw.js` behaviour (anything beyond the marker block, derived `CACHE` and comments) or to `index.html`.
- A hook or permission blocks `sw.js`, `.github/`, `.claude/settings.json` or `CLAUDE.md`, or a hook would need changing.
- An action's commit SHA cannot be resolved from GitHub, or a step would need an action beyond the ones listed.
- The hash differs between two runs or machines (line endings, ordering) after two attempts to fix it.
