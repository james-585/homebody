# Known issues

Seeded from the product/code review of the shipped app (index.html, sw.js, manifest.json). Owners are the agents who should triage each item. Status: Open unless stated.

## Reliability and data
| # | Issue | Owner |
| --- | --- | --- |
| K1 | `sw.js` precaches only `manifest.json`, and `index.html` is network-first with an empty cache as fallback, so the app does not open offline. Fonts come from Google Fonts. | storage-sync-engineer |
| K2 | All data lives in one localStorage blob (`vaultfit_v1`). Only a manual export protects it; storage can be evicted or cleared. Writes fail silently (`persistSave` swallows errors). | storage-sync-engineer |
| K3 | Exercises are matched by name string; bilateral sides are a " (Left)" / " (Right)" suffix. Renaming breaks history, PRs and plans. | exercise-data-curator, architect |

Volume, recovery, PR and strength-level code skips unmatched names, so stats are silently undercounted. Fixture: tests/fixtures/legacy/vaultfit_v1_export.sanitized.json. | exercise-data-curator, storage-sync-engineer |
| K17 | Stored records come in mixed shapes: workouts with and without `notes` / `rpe` (47 of 149 have no RPE), and two side encodings (474 entries use the " (Left)" / " (Right)" name suffix, only 248 also carry `bilateral` / `side`). ## Engineering
| # | Issue | Owner |
| --- | --- | --- |
| K14 | One ~670 KB, ~7,800-line file with global functions, inline handlers and no automated tests. | architect, test-engineer |
| K15 | Names are interpolated into HTML via template literals and inline handlers; `escHtml` does not protect JS string contexts inside `onclick`. Needs an audit. | security-reviewer |
| K20 | **Shared hosting origin (security-reviewer, T3).** On GitHub Pages every project under the same `<user>.github.io` shares one origin, so `localStorage` (`vaultfit_v1`: weight, body fat, history) and Cache Storage are shared with sibling repos. A sibling with an XSS or third-party script could read the data, write a malicious `index.html` into the `homebody-<VERSION>` cache (served cache-first), or a root user-site could register a service worker at scope `/` that controls the app. The `homebody-*` cache-deletion rule only stops HomeBody deleting other apps' caches. Fix is an ADR to host on a dedicated origin (custom domain or dedicated account); moving origins strands `localStorage`, so it needs a data-carry plan (principle 1). Also unresolved: no Content-Security-Policy (inline handlers limit its value), and precaching a redirected response would break offline start (reject `!ok \|\| redirected` at install). Assumption A3 in docs/plans/m1.md (Pages sub-path) depends on this. | architect, security-reviewer, devops-engineer |
| K21 | The toast container `#m-toasts` has no live region (`role="status"`), so screen readers do not hear toasts such as "Workout saved" or the T4 "Ready to use offline" (found by product-designer in the T4 update-notice spec). T4 gives Profile -> About an announced Offline status line instead. Adding the attribute touches `mToast` and its container, outside T4. | accessibility-performance-reviewer, frontend-engineer |
| K22 | **Dead-tap zone over the FAB (found by product-designer, T4a review).** `#m-fab-tray` (z-index 9600, `pointer-events:auto`) keeps the layout box of its three hidden children (Wake, 30s, Rest), so an invisible box about 78x204 px reaches about 156 px above the visible FAB and swallows taps on every page in the shipped app (measured at 375, 390 and 430 wide). It was hidden until T4 put controls under it (About Copy and Update, the right side of the update card). Fix in T4a Amendment 2: `pointer-events:none` on the tray with the FAB and visible children re-enabled, plus a real-touch e2e. Check other pages for controls near the bottom right that lost taps. | frontend-engineer, accessibility-performance-reviewer |
| K23 | **The FAB sits above every sheet (found by product-designer, T4a re-check).** The FAB (z-index 9600) floats over `.modal-overlay` sheets (z-index 200) and covers the right end of actions such as "Confirm Import", "Save Changes" and the plan-edit input at 375, 390 and 430 wide; a real tap at 92% of "Confirm Import" at 390 opened the FAB tray instead. Fix: hide the FAB, or drop it below 200, while any `.modal-overlay.open` is showing (the rest timer stays reachable in workout mode). Needs its own small task and a real-touch test. | frontend-engineer, product-designer |
| K24 | **Visual and copy findings from the T4a re-check, for the design milestone (M2):** the calendar emoji renders as "July 17" on Apple beside "No session planned today"; the light-theme header gradient ends in navy `#0a1828` on Train and Profile (a dark-mode leftover, low-contrast STREAK and SESSIONS labels); the greeting reads "GOOD MORNING 👋, TEST" (comma after the emoji, uppercased name); the ⚡ FAB is on screen on every page even with no workout running and sits over list content (a product question). | K25 | **`wmPersist` swallowed its own write errors (found by storage-sync-engineer, T5).** A full quota during a workout was silent until Finish. T8 should make those toasts wait for the store result or say "logged". | frontend-engineer, product-designer |
